# VetRx Phase 9: Production Failure Response Matrix

This matrix establishes the detection signatures, severity classification, root cause diagnostics, containment procedures, and verification steps across all 10 production failure scenarios.

---

## Failure Response Matrix

| Scenario | Severity | Detection Signature | Primary Root Causes | Immediate Containment & Recovery Procedure | Verification Step |
| :--- | :---: | :--- | :--- | :--- | :--- |
| **1. Backend API Unavailable** | **P1** | API returns 502 Bad Gateway; `/api/ready` unreachable. | Unhandled node exception, OOM kill, bad container deployment. | 1. Inspect logs: `docker logs vetrx-backend-prod --tail 50`.<br>2. Restart: `docker compose -f docker-compose.prod.yml restart vetrx-backend-prod`.<br>3. If code defect, execute rollback. | `curl -i https://vetrx.adcpmalappuram.in/api/ready` returns HTTP 200 OK. |
| **2. Frontend SPA Unavailable** | **P1** | Browser loads 502 Bad Gateway at `/`; container status shows `Exited`. | Port 3000 conflict, NGINX container crash, bad static asset build. | 1. Restart: `docker compose -f docker-compose.prod.yml restart vetrx-frontend-prod`.<br>2. Check `docker logs vetrx-frontend-prod`. | Root URL loads index HTML in < 200 ms. |
| **3. PostgreSQL Unavailable** | **P0** | `/api/ready` returns HTTP 503 `database: disconnected`; DB connection refused. | Postgres crash, disk full, corrupted data volume. | 1. Restart container: `docker compose -f docker-compose.prod.yml restart vetrx-postgres-prod`.<br>2. Check volume logs.<br>3. If corrupted, execute backup restore. | `/api/ready` returns `status: "ready"`, `database: "connected"`. |
| **4. Host NGINX Proxy Down** | **P0** | Connection refused to `https://vetrx.adcpmalappuram.in`. | NGINX service crash, configuration syntax error, port 80/443 conflict. | 1. Test syntax: `sudo nginx -t`.<br>2. Restart service: `sudo systemctl restart nginx`.<br>3. Check systemd journal: `journalctl -u nginx -n 20`. | Domain resolves cleanly over HTTPS. |
| **5. Host Disk Pressure (> 85%)** | **P1** | Monitoring alert or `df -h /` shows < 15% (4.5 GiB) free space. | Docker cache buildup, unrotated log files, excessive backup retention. | 1. Prune unused docker layers: `docker system prune -af --volumes=false`.<br>2. Clean journal logs: `sudo journalctl --vacuum-size=200M`.<br>3. Verify backup retention script. | `df -h /` shows >= 25% free disk capacity. |
| **6. Database Corruption** | **P0** | PostgreSQL logs report block checksum failures or invalid page headers. | Unclean host power cut, hardware I/O error, volume corruption. | 1. Stop backend: `docker stop vetrx-backend-prod`.<br>2. Restore latest valid daily dump: `gunzip -c /home/ncms/backups/vetrx/<LATEST>.sql.gz \| docker exec -i vetrx-postgres-prod psql -U vetrx -d vetrx`.<br>3. Restart backend. | Database accepts queries and `/api/ready` returns 200. |
| **7. Backup Job Failure** | **P1** | `/home/ncms/backups/vetrx/backup.log` reports non-zero exit code or missing file. | PostgreSQL credentials altered, disk full, gzip compression error. | 1. Inspect `tail -n 20 /home/ncms/backups/vetrx/backup.log`.<br>2. Run manual backup: `/home/ncms/scripts/backup_vetrx_db.sh`.<br>3. Verify gzip integrity: `gzip -t /home/ncms/backups/vetrx/<NEW_FILE>.sql.gz`. | Non-empty `.sql.gz` archive present in storage. |
| **8. TLS / SSL Certificate Failure** | **P1** | Browser reports `NET::ERR_CERT_DATE_INVALID` or SSL handshake failure. | Let's Encrypt renewal failed, certbot cron stopped, rate limited. | 1. Force renew: `sudo certbot renew --nginx --force-renewal`.<br>2. Reload NGINX: `sudo systemctl reload nginx`.<br>3. Test SSL handshake: `openssl s_client -connect vetrx.adcpmalappuram.in:443`. | Browser loads site with valid TLS 1.3 lock icon. |
| **9. Deployment Failure** | **P1** | Post-deploy test failure, white screen of death, or unhandled 500s. | Bad bundle, missing environment variable, incompatible migration. | Execute Rollback Runbook (`docs/PHASE-7-ROLLBACK-RUNBOOK.md`):<br>`git checkout <STABLE_SHA>` $\rightarrow$ rebuild containers $\rightarrow$ verify health. | All 29 backend tests & Phase 6 integration pass. |
| **10. Security / Tenant Incident** | **P0 (CRITICAL BLOCKER)** | Practice A observes data belonging to Practice B or unauthorized API access. | Middleware scoping bug, trusted client header, broken auth guard. | 1. **IMMEDIATELY CONTAIN**: Place NGINX into maintenance mode.<br>2. Revert offending commit immediately.<br>3. Audit `AuditLog` table for data access.<br>4. Re-deploy verified stable release. | Execute `test_two_account_isolation.mjs` with 100% pass. |
